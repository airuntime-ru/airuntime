# Презентация решения

`presentation.pdf` — итоговый файл для сдачи. Он **не хранится в git**: Chrome растеризует
градиенты и звёздное поле, и файл выходит за лимит на размер бинарников в репозитории.
В git лежит исходник `deck.html` — правки видны в диффе, а PDF собирается одной командой.

## Пересобрать

```bash
chrome --headless --disable-gpu --no-pdf-header-footer \
  --virtual-time-budget=12000 \
  --print-to-pdf=docs/max-presentation/presentation.pdf \
  "file:///$(pwd)/docs/max-presentation/deck.html"
```

Подойдёт любой Chromium. Страница получается 960×540 pt, то есть ровно 16:9 при
`@page { size: 1280px 720px }` и `.slide` того же размера — если развести эти два значения,
Chrome начнёт масштабировать и по краям полезут полосы.

## Что нужно заполнить перед сдачей

Помечено в тексте словом `ЗАПОЛНИТЬ`:

- **Слайд 1** — commit hash той версии, которую сдаёте, и домен мини-приложения.
- **Слайд 2** — название команды, участники и роли.

Токен бота в презентацию не вписан намеренно: по правилам его передают отдельно, а
в репозитории секретов быть не должно.

## Оформление

Колода оформлена как коллаборация двух брендов:

- **MAX / VK** — синий `#0077ff` и фиолетовый `#7b2cff`, «лестница» из пикселей как
  фирменный мотив, плоские светлые поверхности.
- **AIRuntime** — глубокий космос `#05070f`, звёздное поле (тот же SVG-тайл, что в
  `frontend/src/app/globals.css`) и настоящий логотип из `frontend/public/brand/`.

Связующий элемент — градиент MAX-синий → фиолетовый: он же в «галочке» надзаголовка,
в верхней кромке ключевых карточек и в номерах шагов. Тёмные «космические» слайды
(архитектура, масштабирование, источники) чередуются со светлыми — это ритм, а не декор:
на тёмных говорим про движок, на светлых — про продукт.

Обложка разрезана по диагонали: слева градиент MAX, справа космос AIRuntime, по шву —
та самая лестница, переходящая из одного мира в другой.

`print-color-adjust: exact` обязателен: без него Chrome печатает тёмные слайды белыми.

## Скриншоты

`shot-*.png` сняты с работающего мини-приложения при эмуляции вьюпорта 390×620 —
это настоящие экраны целиком, а не кадрированные куски: подрезанный скриншот читается
как сломанный слайд. Индикатор dev-режима Next.js при съёмке скрывается
(`nextjs-portal { display: none }`), иначе он запекается в каждый кадр. Пересъёмка: поднять фронтенд, открыть `/max`,
снять через CDP с `Emulation.setDeviceMetricsOverride` (обычный `--window-size` на Windows
включает рамку окна и даёт подрезанный кадр).

## Проверка вёрстки

Слайды фиксированной высоты с `overflow: hidden`, поэтому переполнение не видно глазом —
оно просто обрезает контент. Перед пересборкой стоит проверить, что низ содержимого каждого
слайда не заходит за нижний паддинг: пройтись по `.slide`, взять максимальный `bottom`
среди потомков (кроме `.body`, `.num`, `.brandline` и содержимого `svg`) и сравнить с
`height - padding-bottom`.
