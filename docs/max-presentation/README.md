# Презентация решения

Одна колода в двух форматах — под разные задачи:

| Файл | Что это | В git |
|---|---|---|
| `deck.html` | исходник PDF-версии, правки видны в диффе | да |
| `presentation.pdf` | итоговый PDF для сдачи | нет, генерируется |
| `build-pptx.js` | генератор PowerPoint-версии | да |
| `presentation.pptx` | редактируемая колода для PowerPoint | да |

PDF не хранится в git: Chrome растеризует градиенты и звёздное поле, и файл выходит за
лимит на размер бинарников. `.pptx` укладывается, поэтому лежит рядом с генератором.

## Пересобрать PDF

```bash
chrome --headless --disable-gpu --no-pdf-header-footer \
  --virtual-time-budget=12000 \
  --print-to-pdf=docs/max-presentation/presentation.pdf \
  "file:///$(pwd)/docs/max-presentation/deck.html"
```

Подойдёт любой Chromium. Страница получается 960×540 pt, то есть ровно 16:9 при
`@page { size: 1280px 720px }` и `.slide` того же размера — если развести эти два значения,
Chrome начнёт масштабировать и по краям полезут полосы.

## Пересобрать PowerPoint

```bash
cd docs/max-presentation
npm install pptxgenjs --no-save
node build-pptx.js
```

Всё, что pptxgenjs нарисовать не умеет — градиенты, звёздное поле, скруглённые углы у
скриншотов, — приезжает картинками из `make-assets.py`:

| Файл | Где |
|---|---|
| `bg-cover.jpg` | фон обложки и финального слайда — его же берёт `deck.html`, поэтому обе версии открываются одинаково |
| `bg-dark.png` | «космические» слайды |
| `screen-*.png` | скриншоты со скруглёнными углами для рамок телефонов в `.pptx` |
| `bubble-owner.png` | градиентный пузырь сообщения на обложке |
| `qr-bot.png` | QR-код на бота для финального слайда |
| `mark-airuntime.png` | знак AIRuntime, уменьшенный из `frontend/public/brand/logo-mark.png` |

Размер тут часть задачи: pptxgenjs вставляет картинку заново на каждый слайд, где она
используется, а в репозиторий не проходят файлы больше 1000 КБ. Поэтому фоны — JPEG,
скриншоты — палитровые PNG, и `.pptx` весит около 800 КБ.

Проверка после сборки обязательна — pptxgenjs умеет выдавать XML, который PowerPoint
не откроет:

```bash
python <skills>/pptx/scripts/office/validate.py presentation.pptx
```

## Что нужно заполнить перед сдачей

- **Слайд 2** — `[Название команды]` и `[Участники и роли]`: квадратные скобки и пунктир
  оставлены намеренно, чтобы незаполненное поле нельзя было принять за готовый текст.
- **Слайд 1** — commit hash проставлен в обоих форматах; после последнего коммита перед
  сдачей его стоит обновить.

Править нужно **в обоих** форматах: они собираются из разных исходников.

Токен бота в презентацию не вписан намеренно: по правилам его передают отдельно, а
в репозитории секретов быть не должно.

## Оформление

Колода оформлена как коллаборация двух брендов:

- **MAX / VK** — синий `#0077ff` и фиолетовый `#7b2cff`, «лестница» из пикселей как
  фирменный мотив, плоские светлые поверхности.
- **AIRuntime** — глубокий космос `#05070f`, звёздное поле (тот же SVG-тайл, что в
  `frontend/src/app/globals.css`) и настоящий логотип из `frontend/public/brand/`.

Связующий элемент — градиент MAX-синий → фиолетовый: он же в «галочке» надзаголовка,
в верхней кромке ключевых карточек и в номерах шагов. Тёмные «космические» слайды
(архитектура, масштабирование, источники) чередуются со светлыми — это ритм, а не декор:
на тёмных говорим про движок, на светлых — про продукт.

Обложка и финальный слайд стоят на одном фоне: космос AIRuntime, подсвеченный градиентом
MAX. На обложке продукт показан как переписка, в которой всё и происходит: сообщение
владельца → ответ бота с кнопкой → витрина, которую эта кнопка открывает. Финальный слайд
замыкает колоду и даёт QR-код на бота — попробовать можно, не перепечатывая ссылку.

`print-color-adjust: exact` обязателен: без него Chrome печатает тёмные слайды белыми.

## Скриншоты

`shot-*.png` сняты с работающего мини-приложения при эмуляции вьюпорта 390×780 —
это настоящие экраны целиком, а не кадрированные куски: подрезанный скриншот читается
как сломанный слайд. Индикатор dev-режима Next.js при съёмке скрывается
(`nextjs-portal { display: none }`), иначе он запекается в каждый кадр. Пересъёмка: поднять фронтенд, открыть `/max`,
снять через CDP с `Emulation.setDeviceMetricsOverride` (обычный `--window-size` на Windows
включает рамку окна и даёт подрезанный кадр).

## Проверка вёрстки

Слайды фиксированной высоты с `overflow: hidden`, поэтому переполнение не видно глазом —
оно просто обрезает контент. Проверять нужно в обе стороны: `.body` центрирует содержимое
по вертикали, и то, что в него не влезло, вылезает **и вниз, на футер, и вверх, на
заголовок** — именно так телефоны на слайде 7 однажды наехали на название слайда. Перед
пересборкой пройтись по `.slide` и убедиться, что:

- ни один потомок `.body` не начинается выше низа `.slide-head`;
- ни один текстовый блок, картинка или карточка не пересекается с `.foot`;
- на обложке и финальном слайде блоки не пересекаются друг с другом (исключение —
  ответ бота, который намеренно лежит на пустой нижней части телефона).

У картинок в рамках задан `aspect-ratio`, поэтому вёрстка не зависит от того, загрузился
ли скриншот, — и проверка честная даже на снимке страницы без картинок.
